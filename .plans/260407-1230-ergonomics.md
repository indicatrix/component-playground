
# Ergonomics

Some early feedback for component playground:
- Working with `add_`, `addWhen_` etc is difficult.
- `Component_` still carries `msg` — is it needed?

## Completed

### Remove `msg` from `Frame` / `Playground`

`Frame` and `Playground` had a `msg` type parameter that only existed for
`StaticFrame`. Interactive frames were already type-erased to `Update t e`.

- Changed `StaticFrame (Html msg)` → `StaticFrame (Html (List e))`
- Removed `msg` from `Frame e t msg` → `Frame e t` and `Playground e t msg` → `Playground e t`
- `processFrame` maps `List e` → `Update t e` via `Update [] effects`
- Updated all signatures in Component.elm, Application.elm, examples, and tests
- Also fixed pre-existing test bug: `val` → `value` field name in `ControlTests.elm` maybe tests

### Explore whether `Component_` still needs `msg`

**Result: yes, `msg` earns its keep.** Components are defined with polymorphic
`msg` (e.g. `Component e t TextFieldModel msg`). The view uses `setter`
opaquely — never constructing `msg` values directly. This means the same
component definition is reusable across different playground configurations.
`msg` only gets pinned to `Update t e` at the `explore`/`example` frame
boundary, which is exactly where it should be.

### Change `add_` / `addWhen_` to use `{ state, toValue }` records

Previously the constructor took two curried args per mapped field
(`i -> (i -> a) -> b`), easy to mix up. Now takes one
`{ state : i, toValue : i -> a }` record per field.

`toControl_` also changed from `( i, Lookup t -> i -> m )` tuple to
`{ state : i, toValue : i -> m }` record. The `Lookup` parameter was
dropped — nobody used it; each field's Lookup dependency is already captured
internally by `addWhen_`.

### Consistent type parameter naming

Renamed type parameters across all types for consistency:

**Internal types** — `ControlI_ e t state final value`:
- `state` — what the control holds (`default`, `update`, `fromType` result)
- `final` — the complete record (`fromType`, `toType`, `controls` read from)
- `value` — what `map` produces

**Exposed types** — use `state` and `value`:
- `Control e t state` (storage = output)
- `Control_ e t state value` (storage ≠ output)
- `Builder e t state value` (state = full record, value = remaining constructor)

Signatures are now self-documenting:

```elm
add_ :
    String
    -> (state -> innerState)
    -> Control_ e t innerState innerValue
    -> Builder e t state ({ state : innerState, toValue : innerState -> innerValue } -> value)
    -> Builder e t state value
```
