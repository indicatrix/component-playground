# Plan: Frame Constructor API Changes

**Date:** 260411-1540  
**Status:** Awaiting answers to open questions

---

## Summary

Three changes to frame constructors in `src/Component.elm`:

1. `explore` gains a `Html msg -> Html msg` wrapper parameter
2. `example` gains a `Html msg -> Html msg` wrapper parameter
3. New frame constructor for non-interactive static variant enumeration

All examples in `examples/src/Index.elm` will be updated to match.

---

## Motivation

Users need to wrap the rendered component output in custom chrome — e.g. a fixed-height div for components that inherit parent height, or a background colour swatch. The wrapper is applied to the component's rendered HTML before it appears in the frame.

The new non-interactive function lets users enumerate multiple model values (variants, states, colour themes) as pure static HTML without controls.

---

## Open Questions (for user)

**Q1 — Breaking vs additive for `explore`/`example`**  
Should the wrapper be a required first argument (breaking API change), or should we add new named variants like `exploreIn`/`exampleIn` while keeping the originals?  
*Leaning toward breaking, since you said "they need to take".*

**Q2 — New function name**  
What should the new non-interactive multi-variant frame constructor be called?  
Candidates: `gallery`, `variants`, `samples`, `showcase`, `previews`.

**Q3 — New function: named or unnamed variants**  
Does each variant get a label/name displayed above it, or is it just a raw list of model values?
```elm
-- Option A: labeled
newFn : List { label : String, model : m } -> (m -> Html Never) -> Frame e t

-- Option B: unlabeled
newFn : List m -> (m -> Html Never) -> Frame e t
```

**Q4 — New function: also takes a wrapper?**  
Should the new function also accept an `Html Never -> Html Never` wrapper (per-variant or for the container), or is the view function sufficient for that?

**Q5 — New function: can it produce effects?**  
Should the view type be `m -> Html Never` (truly static, no messages) or `m -> Html (List e)` (can fire effects but no state changes)?  
*`Html Never` seems cleanest for a pure enumeration.*

## Planned Implementation

### Signature Changes

```elm
-- BEFORE
explore : Component_ e t i m (Update t e) -> Frame e t
example : String -> m -> Component e t m (Update t e) -> Frame e t

-- AFTER
explore : (Html (Update t e) -> Html (Update t e)) -> Component_ e t i m (Update t e) -> Frame e t
example : (Html (Update t e) -> Html (Update t e)) -> String -> m -> Component e t m (Update t e) -> Frame e t

-- NEW (name and exact signature TBD)
gallery : List m -> (m -> Html Never) -> Frame e t
```

### Where the Wrapper is Applied

Option A (preferred): Apply in `makeComponentE` — thread the wrapper into the `render` closure so it wraps `Tuple.first` of the `View (Update t e)`.

- No changes needed to `Component.Internal.Frame` or `Component.Application`
- `makeComponentE` gains a wrapper parameter
- Clean, minimal blast radius

Option B: Store wrapper in `Frame` variant, apply in `Application.elm` `viewInteractiveFrame`.

- Requires changing `Internal.Frame` constructors → touches more code
- More explicit but more churn

### Files to Touch

| File | Change |
|------|--------|
| `src/Component.elm` | Update `explore`, `example` signatures + bodies; add new constructor |
| `src/Component/Internal.elm` | Possibly none (Option A) or add wrapper to `Frame` (Option B) |
| `src/Component/Application.elm` | Possibly none (Option A) or update `viewInteractiveFrame` (Option B) |
| `examples/src/Index.elm` | Update all `explore`/`example` call sites; add example of new constructor |

### Elm Example Usage (after change)

```elm
-- explore with a fixed-height container
Component.explore
    (\inner -> Html.div [ Html.Attributes.style "height" "300px" ] [ inner ])
    Components.textField

-- explore with identity (no wrapper)
Component.explore identity Components.intInput

-- example with a dark background
Component.example
    (\inner -> Html.div [ Html.Attributes.style "background" "#1a1a1a", Html.Attributes.style "padding" "16px" ] [ inner ])
    "Dark variant"
    { label = "Click me" }
    Components.button

-- new non-interactive variants frame (name TBD)
Component.gallery
    [ { label = "Primary", model = { variant = Primary } }
    , { label = "Secondary", model = { variant = Secondary } }
    ]
    (\m -> Buttons.view m)
```
