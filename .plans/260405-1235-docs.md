# Documentation & cleanup

## Context

The control complexity work (260405-1045) is complete. Several cleanup items and a documentation pass are needed before the library is ready for broader use.

---

## 1. Bug: Hidden fields don't update when type changes

`addWhen` conditionally renders controls, but `hidden` fields that depend on the active branch don't update their values when the branch selector changes. Need to investigate whether hidden fields are being reconstructed from stale state when the predicate flips.

Approach: add unit tests that exercise the addWhen/hidden interaction first, then fix driven by the failing tests.

**Files:** `src/Component/Control.elm` (addWhen / hidden interaction), `src/Component/Application.elm` (state reconstruction), tests

---

## 2. Merge `explore_` into `explore`

`explore_` is just `explore` with a less restrictive type signature (`Component_` instead of `Component`). Since `Component` is an alias for `Component_` where `i = m`, `explore_`'s signature already accepts both. Drop `explore_`, rename `explore_` to `explore`.

**Files:** `src/Component.elm`

---

## 3. Reorganise `Control.elm` doc sections

Current grouping puts things like `identifier`, `componentRef`, `custom` in "Other Combinators" which is vague. Proposed:

- **Primitives**: `string`, `int`, `float`, `bool`, `identifier`, `withPresets`, `fromLookup`, `componentRef`, `stringEntry`, `custom`
- **Modifiers**: `withUpdate`, `hidden`, `withDefault`, `withDescription` (as-is)
- **Composing types**: `builder`, `add`, `add_`, `addWhen`, `addWhen_`, `toControl`, `toControl_`, `list`, `maybe`

Simple -> advanced flow. `add` and `add_` end up next to each other.

Open question: does `Type` need to be documented/exposed from `Control`? It's only needed for `stringEntry` users.

**Files:** `src/Component/Control.elm` (module doc comment and exposing order)

---

## 4. Rename `Controls` -> `Control` everywhere

Rename the internal type names and fields, not just docs and comments. The type `Controls e t i a`, constructor `Controls`, `ControlsI_`, and any field names using the plural form should all become singular. Code and docs should be in alignment — it's `Control` everywhere.

**Files:** `src/Component/Internal.elm` (type definitions), `src/Component/Control.elm`, `src/Component/Application.elm`, and all import sites
